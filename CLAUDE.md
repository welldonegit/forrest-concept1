# FORREST Trinity Resort — правила проекта

Лендинг инвестиционного курорта FORREST Trinity Resort (Буковель): около 20 блоков, анимации, десятки фото. Аудитория — инвесторы. Цель по скорости: PageSpeed 90+ на мобильном.

## Стек

- **Сайт:** Astro, статическая сборка (`output: "static"`). JavaScript только там, где он нужен блоку.
- **Админка:** Sanity (бесплатный тариф), Project ID `rxw30lco`, dataset `production`. Studio лежит в `studio/`; подключается на этапе 3, после окончания вёрстки.
- **Хостинг:** Cloudflare Workers со статикой (не Pages). Сборка через Workers Builds, пересборка по Deploy Hook из Sanity. Выкладка — только `npx wrangler deploy --config wrangler.jsonc` (`npm run deploy`): обычный `wrangler deploy` берёт конфиг адаптера Astro без кода Worker. Код Worker — `worker/`, только для `/api/*`.
- **Заявки:** одна серверная функция `POST /api/lead` на Cloudflare Worker.
- **Анимации:** GSAP + ScrollTrigger. Других библиотек анимации не добавлять.
- Новые зависимости — только по запросу.

## Источники истины

- **Вид блоков:** выгрузка из Claude Design в `design-export/`. Изначально она лежала в корне репозитория и перенесена туда первым коммитом без изменений. Верстаем по ней, внешний вид не меняем без запроса. Файлы в `design-export/` не правим: это эталон для сравнения.
- **Токены:** после аудита единственный источник — `src/styles/tokens.css`. Шкалы собираются из выгрузки и утверждаются человеком (`docs/LAYOUT_RULES.md`, этапы 2–4).
- **Логотип и фирменная графика:** только SVG-файлы из выгрузки, не перерисовывать и не перекрашивать.
- Токены (цвета, размеры, отступы, радиусы) лежат в одном файле CSS-переменных. В компонентах нет «сырых» hex и значений шкалы.

## Контент: всё редактируется в Sanity

Правило: если это видит посетитель, это лежит в Sanity. В коде нет текстов, путей к фото и видео, телефонов и ссылок.

- Один документ `landing` с упорядоченным массивом блоков. Каждый блок — свой тип схемы и свой Astro-компонент с тем же именем.
- Тексты интерфейса (кнопки, подписи и ошибки формы, меню, футер, сообщение об успехе) — в документе `siteSettings`.
- Фото — поле `image` с hotspot и переводимым `alt`. У фото есть переключатель «декоративне фото»: включён — `alt` не нужен и выводится пустым; выключен — `alt` обязателен. Видео — поле `file`.
- У каждого поля в схеме понятное название и подсказка на украинском: редактор не разработчик.
- В Studio блоки называются так же, как на сайте, и показывают превью.
- Добавить, скрыть и переставить блок можно из админки без правки кода.
- У каждого блока главной поле «Мови, на яких показувати блок» (`languages`): пусто — блок на всех языках, иначе только на выбранных (фильтр — `getLanding` в `src/lib/content.ts`). Так блоки ukraine-bukovel («Переваги інвестування в Україну», «Фото між блоками», «Буковель») идут только на `/en/`.
- Блоки только для части языков не должны менять страницы других языков: их CSS и JS не попадают в общие `main.css` и `main.js`, а встраиваются только на странице, где блок есть. Исключение из правила токенов для ukraine-bukovel — `docs/LAYOUT_RULES.md`.
- Датасет на бесплатном тарифе публичный: в Sanity нет заявок, токенов и чего-либо приватного.

## Языки

- Список языков задан в одном файле `languages.ts`, который читают и Astro, и Studio. Новый язык = одна строка в этом файле.
- Старт: `uk` (основной) и `en`. Возможен `ru`. Рассчитываем на 10+.
- Адреса: основной язык `uk` — в корне без приставки (`/`, `/archive/`, `/thanks/`); остальные — со своей приставкой (`/en/`, `/en/archive/`; будущие — `/ru/` и т. п.). Адреса строит только `src/lib/routes.ts`, в компонентах путей с языком нет. Старые `/uk` и `/uk/…` → 301 на те же адреса без `/uk/` с сохранением параметров запроса (`public/_redirects`).
- Переводимые поля — через `sanity-plugin-internationalized-array` (массив, а не объект с ключами языков: иначе упрёмся в лимит 2 000 атрибутов датасета).
- Нет перевода поля → подставляется `uk`, сборка выводит список пропусков.
- SEO на каждый язык: `title`, `description`, `og`, `hreflang` для всех языков плюс `x-default` на `/`, карта сайта.
- Вёрстка выдерживает текст на 40% длиннее украинского: без фиксированных высот у текстовых блоков, без обрезки, кнопки растут по содержимому.
- Отступы и выравнивание — логическими свойствами CSS (`margin-inline`, `padding-inline`, `text-align: start`), чтобы письмо справа налево можно было включить позже.
- Шрифты Unbounded и Mulish: подмножества latin + cyrillic, локальные `woff2`, `font-display: swap`. Язык с другим алфавитом — сообщить, шрифт не подбирать самому.
- Источник шрифтов — Google Fonts: Unbounded v12 (wght 200–900) и Mulish v18 (wght 200–1000), вариативные файлы скачаны и лежат в `public/fonts/`; адреса — в `src/styles/fonts.css`. Сайт к Google не подключается. Файлы `design-export/assets/fonts` не используются. Новая версия шрифта — только по запросу.

## Заявки: `POST /api/lead`

Полное описание — `docs/LEADS.md`; при расхождении верен он.

Источники (`form` → `form_id`): `finmodel` → `finmodel`, `final` → `final_form`, `quiz` → `quiz`, `apartment` → `apartment_popup`, `world` → `world_popup`, `contact` → `contact_popup`. Таблица — `src/lib/lead-forms.ts`.
- Квиз (выгрузка 2026-11-25): 4 шага с репликами менеджера, без email и согласия, в заявке — мессенджер; после отправки — «Дякуємо».
- Окна «Детальніше» миров WIND / ROCK / SUN (кнопки блока «Три світи»): имя, телефон, способ связи; секция — строкой «Секція» в Telegram и в `note` CRM (отдельного поля нет).
- Попап «Звʼязатися» (кнопка в шапке, выгрузка 2026-11-25): имя (по желанию) и телефон; без JS кнопка — `tel:` из «Контакти».

Порядок строго такой:

1. Проверить ключ повтора (двойное нажатие): повтор получает результат первой отправки. Затем поле-ловушку, лимит частоты, Turnstile и поля. При ошибке вернуть код ошибки; текст ошибки фронт берёт из Sanity.
2. **Сначала** записать заявку в D1 (таблица `leads`: данные, язык, страница, UTM, время, статусы каналов).
3. Пользователю вернуть успех, если заявка записана в D1, даже когда Telegram или CRM недоступны.
4. В фоне (`ctx.waitUntil`) отправить в Telegram и в G-PLUS CRM **независимо**, с таймаутами; результат каждого записать в D1.
5. Не дошло — два повтора: через 10 минут и через час. Потом статус «не доставлена», попыток больше нет, в Telegram одно служебное сообщение о сбое на серию.
6. Cron Trigger раз в 10 минут только проверяет базу; нет заявок к повтору — внешних запросов нет.
7. Канал без ключей — статус «не настроен»; такие заявки после добавления ключей не досылаются.
8. Заявки старше 90 дней удаляются.

G-PLUS CRM (Public API v1, схема — `docs/crm/api_schema.yaml`):

- `POST https://crm.g-plus.app/api/v1/leads?fields=…`, заголовки `Authorization: Token <ключ>` и `Content-Type: application/json`. Успех — HTTP 201.
- Обязательные поля CRM: `contact.name` и `added_at` (ISO 8601, ставит сервер). Телефон обязателен в наших формах и передаётся в `contact.phone_numbers`.
- Отдельные поля: способ связи → `contact.preferred_contact_method`, язык → `contact.language` (`uk` → `ua`; языка нет в списке CRM — не передаём, пишем в `note`), цель → `note_purpose`, формат → `note_section`, площадь → `note_square_from/to`, бюджет → `note_budget` + `note_budget_currency`, объект → `objects`.
- UTM → `data.utm`; запасной вариант — `data.custom_field_values`, если заданы ID полей.
- Пустые поля не передавать: нет email — нет ключа `email`. Длинные значения обрезать по ограничениям схемы.
- `note` начинается с «Заявка з лендінгу Forrest», далее номер заявки, источник, адрес страницы и всё, для чего нет отдельного поля.
- Нет ответа (таймаут, обрыв) — перед повтором искать лид по номеру заявки; нашёлся — отправлено.
- `stage_id`, `source`, ID здания, ID кастомных полей — настройки в `wrangler.jsonc`, не константы в коде.
- Токен — отдельного технического пользователя CRM «Сайт», не живого менеджера.

Секреты (токен CRM, токен Telegram-бота, секретный ключ Turnstile) — только в секретах Worker и в локальном `.dev.vars` вне Git. Их нет в репозитории, в HTML и в клиентском JS. Несекретные настройки (ID чата, этапа, источника, здания, публичный ключ Turnstile) — в `wrangler.jsonc`. Ключей Turnstile по умолчанию в коде нет; боевой домен и превью работают на одной настоящей паре, тестовая пара — только localhost.

Личные данные не попадают в Sanity и в журналы Worker, в том числе в отладке.

Аналитика заявок (решение 2026-11-25, заменяет прежнее «в dataLayer без личных данных»): после каждой успешной заявки — ровно одно событие `generate_lead` в `dataLayer` на странице «Дякуємо»; телефон (E.164) и email, если заполнены, передаются в `user_data` для конверсий Google Ads, GA4 и Facebook в GTM. Личные данные не пишутся в журналы (консоль, Worker) и в `localStorage`; в `sessionStorage` (`lead_event`) живут только до чтения на «Дякуємо». Подробно — `docs/LEADS.md`, «Аналитика».

UTM: скрипт сохраняет `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`, `gclid`, `fbclid`, referrer и страницу входа в cookie `gp_utm` на 30 дней (по последнему переходу) и подставляет в заявку.

## Скорость

- Фото скачиваются из Sanity при сборке и отдаются через `astro:assets`: AVIF, несколько ширин, `width` и `height` заданы всегда.
- Главное фото первого экрана: `loading="eager"`, `fetchpriority="high"`. Всё ниже первого экрана — `loading="lazy"`.
- Один файл статики — не больше 25 MiB. Видео тяжелее не коммитить и не класть в статику, а сообщить.
- GSAP грузится один раз; анимация блока запускается, когда блок подходит к экрану. Анимируем только `transform` и `opacity`.
- `prefers-reduced-motion` — статичный вариант без анимаций.
- Сторонний скрипт один — GTM, грузится отложенно. Исключение — «Дякуємо» с событием заявки: там GTM грузится сразу. Пиксели и виджеты в код не добавлять.
- После каждых 3–4 блоков — замер PageSpeed (мобильный) на превью-сборке, результат в отчёт.

## Доступность

- Семантическая разметка, один `h1` на страницу, порядок заголовков без пропусков.
- Видимый фокус, тач-цели от 44 px, поля формы связаны с подписями.
- Модалы запирают фокус и закрываются по Esc.

## Как работать

- Правила вёрстки, шкалы и переноса анимаций — `docs/LAYOUT_RULES.md`. Читай его перед работой над любым блоком.
- План работ — `docs/ROADMAP.md`. В начале сессии прочитай его и продолжай с первой незакрытой задачи; в конце обнови «Статус» и «Журнал». Правила ведения — в самом файле.
- Команды запускай из корня проекта, без `cd`.
- Один блок = одна задача: схема Sanity → компонент Astro → тестовый контент на `uk` и `en` → проверка на 1440, 1024 и 390.
- Перед большими изменениями — план в две строки и продолжай. Останавливайся только перед удалением файлов или изменением внешнего вида.
- Не хватает данных (текст, фото, ID из CRM) — ставь `TODO:` и сообщай, контент не придумывай.
- Отчёт по задаче: что сделано, какие файлы изменены, что проверено, открытые вопросы. Без пересказа кода.
