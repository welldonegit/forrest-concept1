# FORREST Trinity Resort — правила проекта

Лендинг инвестиционного курорта FORREST Trinity Resort (Буковель): около 20 блоков, анимации, десятки фото. Аудитория — инвесторы. Цель по скорости: PageSpeed 90+ на мобильном.

## Стек

- **Сайт:** Astro, статическая сборка (`output: "static"`). JavaScript только там, где он нужен блоку.
- **Админка:** Sanity (бесплатный тариф). Studio лежит в `studio/`.
- **Хостинг:** Cloudflare Workers со статикой (не Pages). Сборка через Workers Builds, пересборка по Deploy Hook из Sanity.
- **Заявки:** одна серверная функция `POST /api/lead` на Cloudflare Worker.
- **Анимации:** GSAP + ScrollTrigger. Других библиотек анимации не добавлять.
- Новые зависимости — только по запросу.

## Источники истины

- **Вид блоков:** выгрузка из Claude Design в `design-export/`. Изначально она лежала в корне репозитория и перенесена туда первым коммитом без изменений. Верстаем по ней, внешний вид не меняем без запроса. Файлы в `design-export/` не правим: это эталон для сравнения.
- **Токены:** после аудита единственный источник — `src/styles/tokens.css`. Шкалы собираются из выгрузки и утверждаются человеком (`docs/LAYOUT_RULES.md`, этапы 2–4).
- **Логотип и фирменная графика:** только SVG-файлы из выгрузки, не перерисовывать и не перекрашивать.
- Токены (цвета, размеры, отступы, радиусы) лежат в одном файле CSS-переменных. В компонентах нет «сырых» hex и значений шкалы.

## Контент: всё редактируется в Sanity

Правило: если это видит посетитель, это лежит в Sanity. В коде нет текстов, путей к фото и видео, телефонов и ссылок.

- Один документ `landing` с упорядоченным массивом блоков. Каждый блок — свой тип схемы и свой Astro-компонент с тем же именем.
- Тексты интерфейса (кнопки, подписи и ошибки формы, меню, футер, сообщение об успехе) — в документе `siteSettings`.
- Фото — поле `image` с hotspot и обязательным переводимым `alt`. Видео — поле `file`.
- У каждого поля в схеме понятное название и подсказка на украинском: редактор не разработчик.
- В Studio блоки называются так же, как на сайте, и показывают превью.
- Добавить, скрыть и переставить блок можно из админки без правки кода.
- Датасет на бесплатном тарифе публичный: в Sanity нет заявок, токенов и чего-либо приватного.

## Языки

- Список языков задан в одном файле `languages.ts`, который читают и Astro, и Studio. Новый язык = одна строка в этом файле.
- Старт: `uk` (основной) и `en`. Возможен `ru`. Рассчитываем на 10+.
- Адреса: `/uk/`, `/en/`. Корень `/` перенаправляет на `/uk/`.
- Переводимые поля — через `sanity-plugin-internationalized-array` (массив, а не объект с ключами языков: иначе упрёмся в лимит 2 000 атрибутов датасета).
- Нет перевода поля → подставляется `uk`, сборка выводит список пропусков.
- SEO на каждый язык: `title`, `description`, `og`, `hreflang` для всех языков плюс `x-default` на `/uk/`, карта сайта.
- Вёрстка выдерживает текст на 40% длиннее украинского: без фиксированных высот у текстовых блоков, без обрезки, кнопки растут по содержимому.
- Отступы и выравнивание — логическими свойствами CSS (`margin-inline`, `padding-inline`, `text-align: start`), чтобы письмо справа налево можно было включить позже.
- Шрифты Unbounded и Mulish: подмножества latin + cyrillic, локальные `woff2`, `font-display: swap`. Язык с другим алфавитом — сообщить, шрифт не подбирать самому.

## Заявки: `POST /api/lead`

Порядок строго такой:

1. Проверить Turnstile и поля. При ошибке вернуть код ошибки; текст ошибки фронт берёт из Sanity.
2. **Сначала** записать заявку в D1 (таблица `leads`: данные, язык, страница, UTM, время, статусы отправки).
3. Отправить в Telegram и в G-PLUS CRM **независимо** (`Promise.allSettled`), результат каждого записать в D1.
4. Пользователю вернуть успех, если заявка записана в D1, даже когда Telegram или CRM недоступны.
5. Cron Trigger раз в 10 минут повторяет неотправленные (до 5 попыток).
6. Заявки старше 90 дней удаляются.

G-PLUS CRM (Public API v1, документация: https://crm.g-plus.app/api/v1/docs):

- `POST https://crm.g-plus.app/api/v1/leads`, заголовки `Authorization: Token <ключ>` и `Content-Type: application/json`. Успех — HTTP 201.
- Обязательные поля: `contact { name, phone_numbers[] }` и `added_at` (ISO 8601, ставит сервер).
- Необязательные: `contact.email`, `stage_id`, `source`, `note`, `data.custom_field_values` (пять UTM-меток).
- Пустые поля не передавать: нет email — нет ключа `email`.
- В `note`: название формы, выбранный формат инвестиции, способ связи, язык страницы, адрес страницы.
- `stage_id`, `source` и ID кастомных полей UTM — переменные окружения, не константы в коде.
- Токен — отдельного технического пользователя CRM «Сайт», не живого менеджера.

Секреты (токен CRM, токен Telegram-бота, секретный ключ Turnstile) — только в секретах Worker. Их нет в репозитории, в HTML и в клиентском JS.

UTM: скрипт сохраняет `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content` в cookie на 30 дней и подставляет в заявку.

## Скорость

- Фото скачиваются из Sanity при сборке и отдаются через `astro:assets`: AVIF, несколько ширин, `width` и `height` заданы всегда.
- Главное фото первого экрана: `loading="eager"`, `fetchpriority="high"`. Всё ниже первого экрана — `loading="lazy"`.
- Один файл статики — не больше 25 MiB. Видео тяжелее не коммитить и не класть в статику, а сообщить.
- GSAP грузится один раз; анимация блока запускается, когда блок подходит к экрану. Анимируем только `transform` и `opacity`.
- `prefers-reduced-motion` — статичный вариант без анимаций.
- Сторонний скрипт один — GTM, грузится отложенно. Пиксели и виджеты в код не добавлять.
- После каждых 3–4 блоков — замер PageSpeed (мобильный) на превью-сборке, результат в отчёт.

## Доступность

- Семантическая разметка, один `h1` на страницу, порядок заголовков без пропусков.
- Видимый фокус, тач-цели от 44 px, поля формы связаны с подписями.
- Модалы запирают фокус и закрываются по Esc.

## Как работать

- Правила вёрстки, шкалы и переноса анимаций — `docs/LAYOUT_RULES.md`. Читай его перед работой над любым блоком.
- План работ — `docs/ROADMAP.md`. В начале сессии прочитай его и продолжай с первой незакрытой задачи; в конце обнови «Статус» и «Журнал». Правила ведения — в самом файле.
- Команды запускай из корня проекта, без `cd`.
- Один блок = одна задача: схема Sanity → компонент Astro → тестовый контент на `uk` и `en` → проверка на 1440, 1024 и 390.
- Перед большими изменениями — план в две строки и продолжай. Останавливайся только перед удалением файлов или изменением внешнего вида.
- Не хватает данных (текст, фото, ID из CRM) — ставь `TODO:` и сообщай, контент не придумывай.
- Отчёт по задаче: что сделано, какие файлы изменены, что проверено, открытые вопросы. Без пересказа кода.
